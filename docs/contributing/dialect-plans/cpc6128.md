# Amstrad CPC 6128 dialect — implementation plan

> Generated by the `adding-a-target-system` skill on 2026-07-22. A
> **delegation plan** (the `bbcmaster` / `zxspectrum128` pattern) over the
> CPC 464 dialect planned in [cpc464.md](./cpc464.md): the two machines share
> the Locomotive BASIC language layer, the `src/emulator/cpc/` machine and one
> `docs/reference/cpc` page. Stages here are deltas — each depends on the
> corresponding cpc464 stage having landed. The dialect is **not** registered
> until Stage C.

## Target summary

- **id / name:** `cpc6128` / `CPC 6128`
- **CPU / bus pattern:** **delegation over `cpc464`** — imports the language
  layer (with the BASIC 1.1 keyword variant), keyboard and samples from
  `src/dialects/cpc464/`, and instantiates the shared machine as
  `CpcMachine('6128')`. Owns only: the 1.1 keyword selection, its emulator
  model config (128K RAM banking + BASIC 1.1 ROM), `memoryMap.ts`,
  `aiProfile.ts`, its metadata, and its sysvar address table.
- **What actually differs from the 464:**
  - **Locomotive BASIC 1.1** instead of 1.0 — adds `CLEAR INPUT`,
    `COPYCHR$`, `CURSOR`, `DEC$`, `DERR`, `FILL`, `FRAME`,
    `GRAPHICS PAPER`, `GRAPHICS PEN`, `MASK`, `ON BREAK CONT`. Same token
    scheme and line format; the additions are carried behind the
    `locoKeywords('basic11')` variant seam built in cpc464 Stage 1.
  - **128K RAM** — a second 64K bank set switched through the Gate
    Array/PAL RAM-configuration port (`&7Fxx`, `0b11…` configurations
    mapping 16K banks over the base 64K). BASIC itself doesn't use the
    extra RAM (it's for CP/M and bank-switching software), so the memory
    seam models the configurations without changing the BASIC experience.
  - **BASIC/firmware workspace addresses** differ between 1.0 and 1.1 —
    supplied as this dialect's sysvar table, not new code (cpc464 Stage 5
    keys its readers by variant).
  - Grey keyboard styling (same 10×8 matrix and legends layout).
- **Deliberately deferred:** AMSDOS + the µPD765 FDC (disc drive). The 6128
  boots and runs BASIC fine without the AMSDOS ROM; shipping it without an
  FDC would hang disc commands. Ship tape-only first (like the 464), and
  treat AMSDOS/FDC + `.dsk` import as a follow-up (Stage D note). This also
  means `programRamBytes` should be set from what the shipped configuration
  actually reports at boot (`PRINT FRE(0)`): 42619 without AMSDOS, 42249
  once AMSDOS is added — don't hard-code the real machine's 42249 while the
  emulator boots without AMSDOS.
- **Display size:** identical to cpc464 (`640×400`, Modes 0/1/2).
- **Image / tape format:** identical to cpc464 (tokenized program +
  AMSDOS-headered `.bas`, `.cdt`, cassette WAV). On a real 6128 tape I/O
  needs `|TAPE` first — reflect that in `loadInstructions` /
  `saveInstructions`.
- **ROM:** `public/roms/cpc/cpc6128_os.rom` (16K firmware, OS 2.x) +
  `public/roms/cpc/cpc6128_basic.rom` (16K, Locomotive BASIC 1.1) —
  copyright © 1985 Amstrad plc / Locomotive Software, distributed under the
  same Amstrad emulator permission as the 464 ROMs; extend the
  `public/roms/ATTRIBUTION.md` CPC block. _Do not commit a fabricated ROM._
- **Share verb:** `fill` — `FILL` is a BASIC **1.1-only** keyword, mirroring
  how `play` marks the Spectrum 128 (verb added only at Stage C
  registration; bijection test-enforced).
- **Docs:** `docsReference: 'cpc'` — shares the cpc464 Stage 6 page, where
  1.1-only entries carry a tag.
- **Variable lint:** none, same as cpc464 (fully significant names).

## Stage A — Language delta (BASIC 1.1) ⬜

- [ ] `keywords.ts` — `export const cpc6128Keywords = locoKeywords('basic11')`
      (the variant seam from cpc464 Stage 1), with signatures/docs for the
      eleven 1.1 additions
- [ ] `tokenizer.ts` / `detokenizer.ts` — thin re-exports binding the
      `basic11` variant (the `bbcmaster` `BASIC_IV` pattern)
- [ ] `charset.ts` / `language.ts` — re-export the cpc464 charset; language
      support built over `cpc6128Keywords`
- [ ] `constructsByDialect.cpc6128` in `src/editor/constructs.ts` — reuse the
      `cpc464` array (same statement shapes)
- [ ] tests: 1.1 keywords tokenize on cpc6128 and are rejected (with a clear
      error) by cpc464; round-trip parity with the base dialect

**Depends on:** cpc464 Stage 1.
**Verify:** `npm test` + `npm run typecheck`.

## Stage B — Machine variant (128K banking + 1.1 ROM) ⬜

- [ ] `CpcMachine('6128')` in `src/emulator/cpc/` — second 64K RAM, Gate
      Array/PAL RAM-configuration port (`&7Fxx` writes with bits 7–6 = `11`
      select one of the eight standard configurations; the seam was left
      ready in cpc464 Stage 2's `memory.ts`), BASIC 1.1 upper ROM, OS 2.x
      lower ROM, boot-detect against the 6128 boot screen
- [ ] ROMs into `public/roms/cpc/` + `ATTRIBUTION.md` extension
- [ ] `createEmulator` in this dialect returns the '6128' model (rom/ramKb
      opts ignored — the machine manages its own ROM set and 128K, like the
      Spectrum 128)
- [ ] test: boot to `BASIC 1.1`, inject + RUN a program; a banking test that
      writes/reads through a `&7Fxx` configuration and restores config 0

**Depends on:** cpc464 Stage 2; Stage A for the injected program bytes.
**Verify:** emulator boot + banking tests pass.

## Stage C — Wire-up: keyboard theme + register ⬜

- [ ] `keyboardLayout.ts` — re-export the cpc464 layout data with
      `theme: 'vk-theme-cpc6128'` (grey 6128 caps; optional CSS block in
      `src/keyboard/VirtualKeyboard.css`)
- [ ] `samples.ts` — re-export the cpc464 samples (they are valid 1.1
      programs); optionally showcase a 1.1 feature (e.g. `FILL` in
      `circles`) in a later polish pass
- [ ] `aiProfile.ts` — Locomotive BASIC **1.1** prompt (may use the eleven
      additions; note tape I/O needs `|TAPE`)
- [ ] `index.ts` — assemble the `Dialect` (`docsReference: 'cpc'`,
      `programRamBytes` from the shipped boot configuration — see target
      summary)
- [ ] **register in `src/dialects/registry.ts` (directly after `cpc464`) and
      add `{ verb: 'fill', dialectId: 'cpc6128' }` to `SHARE_VERBS` in the
      same change** (bijection test)
- [ ] tests: samples tokenize under 1.1, layout validation reused

**Depends on:** Stages A–B; cpc464 Stage 3 (layout + samples exist).
**Verify:** `npm run typecheck` + `npm test` + `npm run dev` smoke +
`npm run e2e`.

## Stage D — Memory map, introspection & docs deltas ⬜

- [ ] `memoryMap.ts` — own map: same 64K main layout as cpc464 with
      1.1-workspace labels, plus a note-level treatment of the banked 128K
      (main map stays `addressSpace: 0x10000`; the extra banks are described
      in region notes, the Spectrum 128 precedent)
- [ ] `memoryBlocks.ts` — reuse cpc464's figures if HIMEM/defaults match the
      shipped configuration, else own the deltas
- [ ] sysvar address table for BASIC 1.1 → `readVariables()` /
      `readReport()` / `readMemoryStats()` through the variant-keyed readers
      from cpc464 Stage 5
- [ ] transfer parity: reuse cpc464 `targets.ts`/`audio` with 6128
      `|TAPE`-aware load/save instructions (`.cdt` and WAV are
      format-identical)
- [ ] docs delta: ensure every 1.1-only keyword in
      `docs/reference/data/cpc.ts` carries the 1.1 tag; roadmap row update
- [ ] follow-up (not this stage): AMSDOS + FDC 765 + `.dsk` import/export;
      revisit `programRamBytes` (42249) and disc build targets when it lands
- [ ] tests: memory-map invariants, 1.1 sysvar reads, live-vars parity

**Depends on:** Stage B–C; cpc464 Stages 4–6 for the shared pieces.
**Verify:** memory-map tests; variable watcher live on a 6128 program;
`npm run docs:dev` renders the shared CPC page with 1.1 tags.
