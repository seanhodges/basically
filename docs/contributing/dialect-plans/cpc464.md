# Amstrad CPC 464 dialect — implementation plan

> Generated by the `adding-a-target-system` skill on 2026-07-22. Each stage is a
> medium, single-session task for the coding agent. Run them in order; the
> scaffolding under `src/dialects/cpc464/` is throwing stubs until filled in.
> The dialect is **not** registered until Stage 3.

This plan is one half of a pair: the **CPC 6128** is planned alongside it in
[cpc6128.md](./cpc6128.md) as a delegation sibling (the `bbcmaster` /
`zxspectrum128` pattern). The two machines share the Locomotive BASIC language
layer, the `src/emulator/cpc/` machine, and one `docs/reference/cpc` page; the
6128 adds bank-switched 128K RAM and Locomotive BASIC 1.1. Build this plan
first — every 6128 stage leans on the corresponding stage here. Shared pieces
(the keyword variant seam, the `CpcMachine` model parameter, the docs page)
are called out in the stages below so the 464 work doesn't have to be
retrofitted later.

## Target summary

- **id / name:** `cpc464` / `CPC 464`
- **CPU / bus pattern:** in-tree bus over the vendored Z80 core
  (`src/emulator/z80/`), in a new shared machine folder **`src/emulator/cpc/`**
  (the `src/emulator/vic20/` / `pet/` precedent: an in-tree bus shared by
  sibling dialects lives under `src/emulator/`, not inside one dialect
  folder). This is the roadmap's Tier 4: the gating work is the video — Gate
  Array (27-colour palette, mode select, ROM paging, 300Hz interrupt divider) +
  CRTC 6845 raster generation — plus the 8255 PPI (keyboard/vsync/tape) and the
  AY-3-8912 PSG (reuse the 128K Spectrum's implementation, see below).
- **Display size:** `displaySize: { width: 640, height: 400 }` — all three
  screen modes render into one 640-wide canvas (Mode 0 = 160×200 with 4×-wide
  pixels, Mode 1 = 320×200 with 2×-wide, Mode 2 = 640×200 native), 200 scan
  lines doubled to 400 for aspect. Border cropped, like the Sinclair machines.
- **Image / tape format:** the tokenized Locomotive BASIC program area is the
  image (line records `[u16 LE length][u16 LE line number][tokens…][0x00]`,
  program terminated by a zero length word; numeric constants stored in binary,
  not ASCII). File containers: AMSDOS-headered `.bas` (128-byte header +
  checksum) and `.cdt` (TZX-derived) tape images. Cassette WAV via the CPC
  firmware tape scheme (2K blocks of 256-byte CRC'd segments, 1000/2000 baud).
- **ROM:** `public/roms/cpc/cpc464_os.rom` (16K lower/firmware) +
  `public/roms/cpc/cpc464_basic.rom` (16K upper, Locomotive BASIC 1.0) —
  copyright © 1984 Amstrad plc / Locomotive Software. Amstrad has long granted
  permission to distribute its CPC firmware ROMs with emulators provided the
  copyright notice stays intact (the same stance as its Sinclair ROMs; the
  basis on which WinAPE, Arnold, JavaCPC and CPCemu ship them). Add the
  attribution block to `public/roms/ATTRIBUTION.md` in Stage 2. _Do not commit
  a fabricated ROM._
- **Share verb:** `mode` — `MODE` is the iconic Locomotive BASIC screen-mode
  command; unique in `src/player/routes.ts` `SHARE_VERBS` (bijection with the
  registry is test-enforced; added only at Stage 3 registration).
- **Reuse:** `src/emulator/z80/` (vendored CPU, MIT); the AY-3-8912 PSG already
  implemented at `src/dialects/zxspectrum128/emulator/ay.ts` (the CPC drives
  the identical chip through the PPI — factor it out to a shared module, e.g.
  `src/emulator/ay/`, rather than duplicating; the 128K Spectrum keeps working
  off the moved module); `src/transfer/wav.ts` + `audioRecorder.ts` for
  cassette WAV; `src/editor/basicLanguage.ts` options (`hexPrefix: '&'`,
  `binaryPrefix: '&X'`, `suffixChars: '$%!'`).
- **License note:** no new npm dependency — everything is in-tree over the MIT
  Z80 core.
- **Variable lint:** none needed. Locomotive BASIC names are up to 40
  characters, **all significant**, with `%`/`!`/`$` type suffixes — like BBC
  BASIC there is no truncation/collision rule to lint, so no
  `cpc464VariableErrors` wrapper is added to `src/editor/variableLint.ts`
  (BBC precedent; embedded-keyword acceptance is the tokenizer's job).
- **Primary references:** SOFT968 (the Amstrad CPC firmware guide) for
  firmware/system variables and the tape scheme; the CPCWiki Locomotive BASIC
  token table for token bytes; the CPC464 BASIC manual for keyword semantics.
  Numeric details quoted in this plan (token prefixes, addresses, byte
  budgets) are from these sources — re-verify each against the real ROM
  behaviour in the emulator as its stage lands.

## Stage 1 — Language core ⬜

Text ↔ tokenized program bytes; no emulator, no registry change. This is the
most intricate tokenizer in the repo so far: Locomotive BASIC stores numeric
constants **in binary**, so round-tripping is more than a keyword table.

- [ ] `keywords.ts` — `KeywordInfo[]` from the Locomotive BASIC 1.0 token
      table: single-byte statement tokens in the `&80–&FF` range, two-byte
      `&FF`-prefixed function tokens (`SIN`, `CHR$`, …). Build in a **variant
      seam** from day one (the `bbcmicro` `BASIC_IV` / C64 `CbmVariant`
      precedent): `locoKeywords(variant: 'basic10' | 'basic11')`, with the 1.1
      additions (`CLEAR INPUT`, `COPYCHR$`, `CURSOR`, `DEC$`, `DERR`, `FILL`,
      `FRAME`, `GRAPHICS PAPER`, `GRAPHICS PEN`, `MASK`, `ON BREAK CONT`)
      carried in the same table behind the flag, so the cpc6128 dialect is one
      import away. Include `kind`, signatures and one-line docs; include the
      `?`-for-`PRINT` shorthand and multi-word keywords (`ON BREAK GOSUB`,
      `SPEED WRITE`, `SYMBOL AFTER`, …).
- [ ] `charset.ts` — `CharsetMapping` for the CPC's 256-glyph set: 32–126
      near-ASCII, 127–255 the block-graphics / symbol / accented range, with
      unicode forms preferred and `{...}` escapes for the rest (follow the
      shipped dialects' total-charset convention; scaffold the escape table in
      Stage 6 with `npm run gen:escapes`).
- [ ] `language.ts` — `languageSupport()` + `completionSource` via
      `buildCompletionSource`; `BasicLanguageOptions`: `suffixChars: '$%!'`,
      `hexPrefix: '&'`, `binaryPrefix: '&X'` (Locomotive hex `&7F00` and
      binary `&X101` literals).
- [ ] `constructsByDialect.cpc464` entry in `src/editor/constructs.ts` —
      `IF … THEN … ELSE` (Locomotive has real `ELSE`), `FOR…NEXT`,
      `WHILE…WEND`, `GOSUB`, string-arg commands (`PRINT`, `LOAD`, `SAVE`,
      `CHAIN`), common functions.
- [ ] ~~variableLint wrapper~~ — intentionally none (see target summary).
- [ ] `tokenizer.ts` / `detokenizer.ts` — line records
      `[u16 LE total line length][u16 LE line number][token bytes][0x00]`,
      program terminated by `0x0000`; numeric-constant encodings (`&0E`–`&18`
      small integers 0–10, `&19` byte, `&1A` 16-bit int, `&1B` binary, `&1C`
      hex, `&1E` line number, `&1F` 5-byte float) and suffix-coded inline
      variable names. Collect `TokenizeError[]` (1-based line, 0-based
      column), never throw; statement-shape lint is non-fatal. The
      detokenizer must reformat binary numerics losslessly (hex back to `&…`,
      floats to Locomotive's display form).
- [ ] `basfile.ts` — image builder/parser: raw tokenized program ↔ the
      AMSDOS 128-byte header container (type byte, length fields, 16-bit
      checksum), so `tokenize().image` is directly loadable and `.bas` files
      with or without the header import cleanly.
- [ ] `lint` wired through `tokenize`
- [ ] tests: tokenizer round-trip (incl. every numeric encoding and a
      1.0-vs-1.1 keyword gate check), charset totality, AMSDOS
      header/checksum round-trip

**Depends on:** the `Dialect` contract only.
**Verify:** `npm test` + `npm run typecheck`.

## Stage 2 — Emulator core ⬜

The Tier 4 gating stage. New shared machine folder `src/emulator/cpc/`,
parameterised by model so the 6128 reuses it wholesale.

- [ ] `src/emulator/cpc/cpcMachine.ts` — `CpcMachine(model: '464' | '6128')`
      implementing `MachineEmulator` over the vendored Z80: `reset` /
      `loadProgram` / `runFrame` / `renderTo` / `keyEvent` / `setKey` /
      `releaseAllKeys` / `setSpeed` / `dispose` + `displayWidth` /
      `displayHeight`. 4MHz Z80, 50Hz frame; note (don't initially model) the
      Gate Array's memory-wait stretching of M-cycles to 1µs boundaries.
- [ ] `src/emulator/cpc/memory.ts` — 64K RAM with lower-ROM (firmware) /
      upper-ROM (BASIC) overlay controlled by the Gate Array; a RAM-banking
      seam ready for the 6128's `&7Fxx` PAL configurations (inert on the 464).
- [ ] `src/emulator/cpc/gateArray.ts` — palette (27 hardware colours), pen
      registers, screen mode, ROM enables, interrupt counter (300Hz off
      HSYNC, delayed/cleared per the real chip's rules — BASIC's `EVERY`/
      `AFTER` and the firmware ticker depend on it).
- [ ] `src/emulator/cpc/crtc.ts` — CRTC 6845 (registers R0–R17, HSYNC/VSYNC
      timing, screen address generation) driving the renderer; standard
      firmware register set is the accuracy target, not demo tricks.
- [ ] `src/emulator/cpc/display.ts` — render Modes 0/1/2 from CRTC-addressed
      screen RAM (default `&C000–&FFFF`) into the 640×400 canvas.
- [ ] `src/emulator/cpc/ppi.ts` — 8255 PPI: port A ↔ AY data bus (keyboard
      matrix read through the PSG's I/O port), port B (VSYNC, tape read, …),
      port C (keyboard row select, tape motor/write, PSG control).
- [ ] `src/emulator/cpc/keyboard.ts` — the 10×8 CPC key matrix (rows selected
      via PPI port C, read via AY port A), physical `keyEvent` map + virtual
      `setKey` tokens (joystick 0 lives in matrix row 9 — groundwork for
      Stage 6's `setJoystick`).
- [ ] AY-3-8912: factor `src/dialects/zxspectrum128/emulator/ay.ts` into a
      shared module (e.g. `src/emulator/ay/`) and drive it through the PPI;
      wire `readAudio` / `audioSampleRate` here if convenient, else defer to
      Stage 6.
- [ ] `loadProgram` — boot to the BASIC `Ready` prompt (detect via firmware
      state, not a fixed frame count), inject the tokenized image at `&170`,
      patch the BASIC program/variable-area pointers, write `opts.blocks`
      into RAM, then type `RUN` through the key matrix (the ZX80/BBC Master
      precedent — OS-version independent).
- [ ] ROMs into `public/roms/cpc/` **+ attribution block in
      `public/roms/ATTRIBUTION.md`** (Amstrad emulator-distribution
      permission, copyright notice intact)
- [ ] `displaySize: { width: 640, height: 400 }` on the dialect
- [ ] test: boot the ROMs, assert the `Amstrad 64K Microcomputer (v1)` /
      `BASIC 1.0` boot screen renders; inject a program, assert on screen RAM

**Depends on:** Stage 1 (charset for display assertions, image builder for
`loadProgram`).
**Verify:** emulator boot test passes.

- [ ] `keyboardLayout.ts` — the CPC 464 keyboard as `KeyboardLayout` data:

      `functionKeys`), the 464's coloured keycaps via a

## Stage 4 — Transfer & tape I/O ⬜

- [ ] `targets.ts` — `BuildTarget[]`: AMSDOS-headered `.bas` (via
      `basfile.ts`), `.cdt` tape image (TZX-derived container carrying the
      firmware block scheme), cassette `.wav` (via `audio`); mark the tape

- [ ] `audio` — `buildSamples` + `decodeSamples` implementing the CPC

- [ ] `binaryImports` — `.cdt` ("Import .CDT…") and tokenized `.bas`
      (sniff the AMSDOS header / binary line records so text `.bas` still
      opens as source); route through `detokenizeWithReport` with
      import-fidelity warnings
- [ ] tests: cassette encode→decode round-trip, `.cdt` container round-trip

**Depends on:** Stage 1 (tokenizer/detokenizer, image builder).
**Verify:** audio round-trip test + import/export in the app.

## Stage 5 — Memory map & runtime introspection ⬜

- [ ] `memoryMap.ts` — `MemoryMap` over the 64K space: low firmware/RST area
      (`&0000–&003F`), firmware + BASIC workspace up to `&016F`, BASIC
      program area from `&0170`, variables/heap above it, strings descending
      below HIMEM (default `&AB7F`), BASIC fixed workspace + firmware
      variables and jumpblocks (`&AC00–&BFFF`, incl. the `&BB00+` jumpblock),
      screen `&C000–&FFFF`; note the ROM overlays share addresses with RAM
      (map shows the RAM view, as the Spectrum 128 map does for paging).
      `addressNotation: 'hex'` (Locomotive convention is `&`-hex);
      `memoryWrites: { forms: ['poke'], hexPrefix: '&' }`.
- [ ] `memoryBlocks.ts` — `MemoryBlocksSupport`: `cpu: 'z80'`, valid ranges
      within user RAM, reserved ranges for screen/firmware workspace,
      `programArea()` from `&0170` + slack, `defaultAddress: 0x8000` (below
      default HIMEM; the `MEMORY` command is the on-machine equivalent).
      Machine-side injection already landed in Stage 2's `loadProgram`.
- [ ] `sysvars.ts` / `vars.ts` / `reports.ts` → `readVariables()` /
      `readReport()`: walk Locomotive BASIC's variable storage via its system
      pointers (numeric %, !, unsuffixed-float, strings, arrays), read the
      error state (`ERR`/`ERL` equivalents). **The BASIC 1.0 and 1.1
      workspaces sit at different addresses** — key the sysvar table by
      variant so the 6128 supplies its own addresses, not new code.
- [ ] `readMemoryStats()` — used/free from the program-end / HIMEM pointers
      (should agree with `PRINT FRE(0)` = 42619 on a clean 464 boot)
- [ ] memory-activity hooks (`setMemoryActivityRecording` /
      `drainMemoryActivity`) on the CPC bus for the map overlay
- [ ] tests: memory-map layout invariants, block round-trip, live-vars read

**Depends on:** Stages 2–3.
**Verify:** memory-map + blocks tests; variable watcher shows live vars.
