# Altair 8800 dialect — implementation plan

> Generated by the `adding-a-target-system` skill on 2026-08-02. Each stage is a
> medium, single-session task for the coding agent. Run them in order; the
> scaffolding under `src/dialects/altair8800/` is throwing stubs until filled in.
> The dialect is **not** registered until Stage 3.

## Target summary

- **id / name:** `altair8800` / `Altair 8800`
- **Manufacturer / year:** MITS / 1975 — a new picker group (no sibling machine
  ships), and exactly the lower bound `registry.test.ts` allows
- **Blurb:** `The machine that started it all. Runs Altair 8K BASIC.` (54 chars)
- **BASIC:** Altair 8K BASIC — the 4K set plus strings, `PEEK`/`POKE`,
  `OUT`/`INP`, `DEF FN`, `CSAVE`/`CLOAD` and the full maths library
- **CPU / bus pattern:** in-tree bus over the vendored Z80 core in
  `src/emulator/z80/`, executing Intel 8080 object code
- **Display size:** an 80×24 serial terminal at an 8×16 cell →
  `{ width: 640, height: 384 }`
- **Image / tape format:** no standard container. Cassette audio over the 88-ACR
  board (Kansas City Standard, 300 baud), plain-ASCII paper tape, and the
  tokenized image `CSAVE` wrote
- **ROM:** `public/roms/altair8800.rom` — **user-supplied, does not ship**. See
  _The ROM problem_ below; add the `ATTRIBUTION.md` block explaining the absence
- **Share verb:** `csave` — confirmed in the 8K reserved-word list, unique in
  `SHARE_VERBS`, and consistent with the table's cassette-verb house style
  (`load`, `dload`, `cload`). Fallback `inp`. **Not** `console`, which is
  Extended/Disk BASIC rather than 8K
- **`addressNotation`:** `'dec'` — Altair BASIC's `PEEK`/`POKE` take decimal
- **Reuse:** `src/emulator/z80/`, `src/transfer/wav.ts` and the Acorn 300-baud
  KCS encoders, `src/keyboard/templateRows.ts`, `microsoftVariableErrors` in
  `src/editor/variableLint.ts`, and the linked-line tokenizer pattern already
  written twice in `commodore64/tokenizer.ts` and `trs80/tokenizer.ts`
- **License note:** no new npm dependency; the Z80 core is MIT and already
  vendored

## What makes this machine different

Worth reading before starting a stage, because three assumptions that hold for
every other dialect here do not hold for this one.

**There is no video hardware.** Every other machine renders video RAM. The
Altair renders nothing: BASIC writes bytes to a serial port and a terminal on
the other end displays them. So `emulator/terminal.ts` models the _terminal_,
and `emulator/serial.ts` — the 88-2SIO board — carries the machine's entire
personality, standing in for both the video chip and the key matrix. Two ports
do all of it: a status port BASIC polls, and a data port it reads and writes.

**There are no graphics characters.** Plain 7-bit ASCII, so no `graphics.ts`, no
`graphicsPalette`, no `palette: 'graphics'` editor mode, `SEMIGRAPHIC_CODES`
records `null` rather than a guessed range, and the id must **not** join
`e2e/paletteMachines.ts`. It also means the dialect adds no codepoints to the
bundled font subsets, so `fontCoverage.test.ts` needs nothing from it. This is
the simplest charset in the project — and still has to be total and injective.

**There is no ROM, in two separate senses.** The machine had no firmware at all:
you toggled a bootstrap in on the front panel, or loaded BASIC itself from paper
tape, where it ran from RAM at 0x0000. So the image is _copied into RAM_ rather
than mapped read-only, the memory map has no `rom` region, and a stray `POKE`
really can corrupt the interpreter.

### The ROM problem

Altair 8K BASIC is Microsoft copyright with no redistribution grant. Microsoft's
2025 open-source release was the **6502** BASIC (MIT-licensed), not the 8080
Altair BASIC, so there is no image this project can legally ship. The user
supplies their own at `public/roms/altair8800.rom`.

This is the same situation as the TRS-80's Level II ROM — but there a clean-room
interpreter is the shipped default and the ROM path is the optional accuracy
mode, so the machine works out of the box. Here the positions are reversed:
without a user-supplied image the dialect cannot boot, and
`EmulatorPane.tsx:87-97` throws `Failed to fetch ROM (404)`.

**Stage 3 must therefore treat ROM-absence as a designed state**, with a clear
"supply your own Altair 8K BASIC image" message in the emulator pane, and the
machine must stay constructible with an empty image. If a clean-room interpreter
is ever wanted as the default backend, it slots in as an additive Stage 2b —
mirroring `trs80/interpreter/` — and changes nothing else in this plan.

### Two technical risks

1. **8080-on-Z80 divergence.** The Z80 is binary-compatible with the 8080, which
   is why no new core is needed, but two things differ. The 8080's P flag is
   always parity; the Z80 reuses that bit as P/V, holding _overflow_ after
   arithmetic — and 8K BASIC does branch on parity. And `DAA` after a
   subtraction consults the Z80's N flag, which the 8080 does not have. Decide
   in Stage 2 whether to correct these in the adapter or accept the divergence,
   and record which. **Fix it in the machine adapter, never in the vendored
   core** — it is shared with six shipped machines.
2. **Derive, don't guess.** The keyword token bytes, the program base, the
   88-2SIO port numbers and the polarity of its status bits (the ready flags are
   active-low), and `programRamBytes` must each come from a primary source — the
   MITS _Altair BASIC Reference Manual_, the 88-2SIO board manual, or a
   disassembly — and be cited where declared. A wrong token byte produces a
   program that tokenizes cleanly and then fails on real hardware; a wrong status
   polarity produces a machine that boots and then ignores every keystroke.

## Stage 1 — Language core ⬜

Text ↔ tokenized program bytes; no emulator, no registry change.

- [ ] `addresses.ts` — the program base, the interpreter's RAM origin, the
      2SIO ports; each cited to its source
- [ ] `keywords.ts` — the 8K `KeywordInfo[]` table (token byte, kind, signature,
      doc), derived from a disassembly or the MITS manual
- [ ] `charset.ts` — printable ASCII as itself, control codes and the unused
      0x80–0xFF range as `{0xNN}` escapes; total and injective across all 256
      bytes
- [ ] `language.ts` — `languageSupport()` + `completionSource`. Confirm
      `crunched` against the interpreter's CRUNCH routine; `suffixChars` is `$`
      only (8K predates Level II's `%`/`!`/`#` tags); `graphicsEscapes: false`;
      no `hexPrefix`/`binaryPrefix` (`&H` is Disk BASIC)
- [ ] `constructsByDialect.altair8800` in `src/editor/constructs.ts`
- [ ] `altair8800VariableErrors` in `src/editor/variableLint.ts`, over the
      Microsoft-family helper — 8K names are significant to two characters
- [ ] `tokenizer.ts` / `detokenizer.ts` — linked-line layout
      (`[u16 LE link][u16 LE line][body][0x00]`, zero link terminates);
      collect `TokenizeError[]`, never throw
- [ ] `basicImage.ts` — tokenized bytes → loadable image (link chain + the
      text/variable pointers), and parse back
- [ ] `detokenizeWithReport` for import-fidelity warnings
- [ ] tests: tokenizer round-trip, charset totality/injectivity, image-builder
      pointer consistency

**Depends on:** the `Dialect` contract only.
**Verify:** `npm test` + `npm run typecheck`.

## Stage 2 — Emulator core ⬜

- [ ] `emulator/memory.ts` — flat 64K S-100 bus; `loadInterpreter` copies the
      BASIC image into RAM (no ROM mapping)
- [ ] `emulator/serial.ts` — the 88-2SIO: status port, data port in/out, input
      queue
- [ ] `emulator/terminal.ts` — 80×24 grid, CR/LF/backspace/bell, scroll on
      overflow, `renderTo`
- [ ] `emulator/keyboard.ts` — key tokens and DOM events → queued ASCII bytes,
      including CTRL-C (0x03)
- [ ] `emulator/altairMachine.ts` — `MachineEmulator` over the vendored Z80 core
      at `CYCLES_PER_FRAME` (40,000 = 2 MHz ÷ 50); resolve the 8080 flag question
- [ ] stays constructible with an empty ROM image
- [ ] `public/roms/ATTRIBUTION.md` block recording why no image ships
- [ ] test: boot the image, assert the sign-on banner lands in the terminal grid;
      skip (don't fail) when the user-supplied ROM is absent

**Depends on:** Stage 1 (charset for the terminal, image builder for
`loadProgram`).
**Verify:** the boot test passes with a supplied ROM, and the suite stays green
without one.

easy one to miss — it is not in the skill's seam table.

## Stage 5 — Memory map & runtime introspection ⬜

- [ ] `memoryMap.ts` — contiguous ascending regions covering the whole space.
      **No `rom` region** (the interpreter is RAM-resident `system`) and **no
      `screen`/`attributes` regions** (there is no display memory); omit those
      kinds rather than inventing regions for them
- [ ] `memoryBlocks.ts` — `cpu: 'z80'` with a comment explaining that the
      machine runs 8080 code and 8080 assembly is a strict subset (the field is
      typed `'z80' | '6502'`; do not widen the union). Valid range sits above the
      interpreter and program, below the top of fitted RAM
- [ ] `vars.ts` → `readVariables()` — walk the VARTAB/ARYTAB table as the C64 and
      TRS-80 do; omitting it is acceptable if the pointers cannot be pinned down
      (ZX80 and Atom precedent)
- [ ] `reports.ts` → `readReport()` — Altair BASIC _prints_ its errors, so scan
      the terminal grid (closest to `src/emulator/c64/reports.ts`); return null
      rather than a false OK
- [ ] `readMemoryStats()` + memory-activity hooks
- [ ] tests: memory-map layout, block round-trip

**Depends on:** Stages 2–3.
**Verify:** memory-map + blocks tests; the watcher shows live variables.

## Samples

The canonical set, in the canonical order, ported to Altair 8K BASIC. This
machine forces the hardest graceful-degradation call in the project: with no
graphics, no cursor addressing and no screen to clear, `PRINT` to a scrolling
terminal is the entire repertoire. The visual samples therefore plot into a
character grid held in a string array and print the grid.

| `name`         | `title`        | Note                                                                        |
| -------------- | -------------- | --------------------------------------------------------------------------- |
| `hello.bas`    | `Hello world`  | The starter shown for a fresh document.                                     |
| `circles.bas`  | `Circles`      | Keep the Pitteway recurrence the other dialects use.                        |
| `breakout.bas` | `Breakout`     | Whole-frame redraws; check it stays playable at the terminal's scroll rate. |
| `maze.bas`     | `Maze`         | The same fixed wall map, printed as rows of characters.                     |
| `kaleido.bas`  | `Kaleidoscope` | Machine-code block **dropped** — no `USR` block convention here yet, and    |
|                |                | the TRS-80 sets the four-sample precedent.                                  |

`graphicsPalette`, no `e2e/paletteMachines.ts` entry, no `GLYPH_SOURCES` entry
(`glyphSources.ts` degrades via `?? []`), no font-subset re-cut, no new `e2e/`
folder (that layout maps capabilities, not dialects), no `joystickModes`, and no
`readAudio`.
