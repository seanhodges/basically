> Generated by the `adding-a-target-system` skill on 2026-09-01. Each stage is a
> medium, single-session task for the coding agent. Run them in order; the
> scaffolding under `src/dialects/ge235/` is throwing stubs until filled in. The

## Target summary

- **id / name:** `ge235` / `GE-235`
- **CPU / bus pattern:** **in-tree interpreter** — no CPU core, no ROM, no
  assembler, no exec shim. Follows `src/dialects/trs80/interpreter/`.
- **Display size:** a teletype paper roll painted into a fixed canvas, following
  `src/dialects/altair8800/emulator/terminal.ts`. The GE-235's terminal was a
  Teletype Model 33 ASR at **72 columns**; pick the row count with the Altair's
  80×24 as the precedent and set `displaySize` from the cell metrics.
- **Image / tape format:** none native. Program text only; the export is a
  plain-ASCII paper-tape / listing target (`src/dialects/altair8800/targets.ts`
  is the model).
- **ROM:** none. Interpreter dialects need none, and no GE-235 image ships.
- **Share verb:** pick a real Dartmouth BASIC keyword unique in `SHARE_VERBS`
  (`src/player/routes.ts`). `let` is the obvious candidate — Dartmouth BASIC
  required `LET` on every assignment — but check the table for a clash first;
  the bijection with the registry is test-enforced.
- **Reuse:** `src/keyboard/templateRows.ts`, `src/dialects/sampleKit.ts`,
  `src/editor/basicLanguage.ts`, `src/editor/completions.ts`, and the Altair's
  terminal and ASR-33 layout as patterns (read them; do not import across
  dialects).
- **License note:** **unresolved, and it gates two assets only.** A clean-room
  interpreter needs no permission. What does need it is the verbatim 1965 error
  strings and the `LIB/` sample programs, both from an archive that states no
  terms. Treat both as **swappable**: if permission is refused or unanswered,
  paraphrase the error text and use the house sample kit. Nothing else in this
  plan depends on the answer, so no stage is blocked on it.

## Why this machine is unlike the other twenty-one

Three things, and every one of them already has a precedent in the tree:

| Trait                                                    | Precedent to follow                                     |
| -------------------------------------------------------- | ------------------------------------------------------- |
| No video hardware — a scrolling paper roll, not a screen | `altair8800/emulator/terminal.ts`                       |
| No ROM obtainable, so a clean-room interpreter           | `trs80/interpreter/` (18 files, `trs80/index.ts:75`)    |
| Teletype, no key matrix                                  | `altair8800/keyboardLayout.ts` (ASR-33, no CURSOR mode) |

A fourth has no precedent: **it is a 1965 mainframe**, so it sits outside the
era the project currently claims. See Stage 7.

## Research already done — use these, do not re-derive

**The character encoding is solved and certain.** Standard 6-bit BCD, three
characters per 20-bit word in the low 18 bits. Derived by uniquely solving the
`alf` text table in the original compiler image — exactly one consistent answer
existed across the whole image, so there is no ambiguity to resolve:

| Range   | Codes (octal) |
| ------- | ------------- |
| `0`–`9` | `00`–`11`     |
| space   | `60`          |
| `a`–`i` | `21`–`31`     |
| `j`–`r` | `41`–`51`     |
| `s`–`z` | `62`–`71`     |

This is Stage 1's `charset.ts`, and `charset.test.ts` can assert the table
directly as a hard fact.

**The runtime error messages were decoded verbatim from the original binary.**
These are what the machine actually printed, and they belong in the
interpreter's error table (subject to the licensing note above):

> dimension too large · illegal constant · illegal formula · illegal instruction ·
> illegal number · illegal relation · illegal variable · incorrect format ·
> end is not last · ?no end instruction · ?no data · ?undefined function ·
> ?undefined number · ?program too long · ?too much data · ?too many loops ·
> for without next · ?out of data · square root of negative number ·
> ?log of negative number · ?log of zero · program over time limit ·
> test aborted · ?return before gosub · ?subscript error · ?division by zero ·
> ?overflow · underflow · ?zero to a negative power ·
> ?absolute value raised to power · ?gosubs nested too deeply ·
> ?input data not in correct format? retype it

**Corrected in Stage 1:** that list mixes the compile-time and run-time sets,
and no message in either carries a `?`. The exact strings, and where each set
sits in the source, are under Stage 1 below — use those.

**The authoritative language specification** is the proofed compiler source
`BA-1`/`BA-2`/`BA-3` (6,023 lines of GE-235 assembly), at
`dtss.dartmouth.edu/proofed/BASIC/` in
[`larsbrinkhoff/dtss-backup`](https://github.com/larsbrinkhoff/dtss-backup).
Header: `telebasic rev. 1 / basic and teach combined / 8 feb 65`. Read it for the
statement set, operator precedence, `PRINT` zone behaviour and number
formatting. **Do not guess these from later microcomputer BASICs** — the whole
point of this dialect is that it predates them.

**Authentic 1965 programs** for the sample kit live at `DTSS-Win/LIB/` in the
same archive: `GUESS`, `FTBALL`, `QUAD`, `PIE`, `MORT`, `NORMAL`, `RATION`.

**BASIC was compiled, not interpreted.** Kurtz records 1–4 seconds per
compilation, so a brief pause on RUN before any output is authentic behaviour,
not a stall to optimise away.

## Stage 1 — Language core ✅

Text ↔ program bytes; no interpreter, no registry change.

- [x] `keywords.ts` — the statement set is the `q` jump table in `BA-1`, the
      library is the `q2*` chain in the same file. Both differ from what this
      plan expected, and the differences are the dialect: **there is no
      `RESTORE`** (after `r` the decoder accepts only `e`, giving READ, REM and
      RETURN) and **there is no `SGN`** (the library is exactly ABS, ATN, COS,
      EXP, INT, LOG, RND, SIN, SQR, TAN, plus `FNx` from DEF). **`LET` is
      mandatory** — a line opening with a letter reaches the jump table's `a`
      slot, which branches to the error exit, so `10 A=1` is an illegal
      instruction
- [x] `charset.ts` — all 64 codes, not just the letters and digits: `BA-3`'s `s2`
      (BCD code → internal code) and `s` (internal code → what it is) fix the
      whole table between them, and the packed literals confirm the reading
      (`oct 0606037` is space, space, CR). `SEMIGRAPHIC_CODES` is **deferred to
      Stage 7**: `semigraphicsAudit.test.ts` fails on a key that is not a
      registered dialect
- [x] `language.ts` — `graphicsEscapes: false`, `suffixChars: ''` (`$` is
      rejected outright: "$ never legal in regular basic" in `var`), and
      `crunched: true`, because `trans` deletes every blank outside a string
      literal before anything looks at the line — so `P R I N T` is PRINT and
      `GO TO` is GOTO
- [x] `GE235_CONSTRUCTS` in `src/editor/constructs.ts`, **exported by name, not
      added to `constructsByDialect`** — that map is pinned to the registry
      (`constructs.test.ts`, "templates only registered dialects"), so the map
      entry is Stage 7's. Same for `GE235_LEXIS` in `variableLexis.ts`. The SAM
      Coupé entries are the precedent for both
- [x] `ge235VariableErrors` in `src/editor/variableLint.ts`, over
      `singleLetterVariableErrors` with a new `digitSuffix` option: `var10`
      takes a letter, then at most one digit, and rejects a second digit. An
      array name has no room for the digit, `var` reading the bracket straight
      after the letter
- [x] `tokenizer.ts` / `detokenizer.ts` — program bytes are the paper tape: one
      BCD code per line character, `0o37` after each line, `0o55` closing the
      tape. Records are canonical (line number, one space, trimmed body) so
      both round-trip directions are exact
- [x] `lint` wired through `tokenize`, plus the name rules
- [x] tests: `charset.test.ts` (the table as a hard fact, and that the mapping is
      total and injective), `tokenizer.test.ts` (both round-trip directions,
      the framing and the lint), `keywords.test.ts` (the vocabulary, and the
      absences)

**Depends on:** the `Dialect` contract only.
**Verify:** `npm test` + `npm run typecheck`. ✅

### What Stage 1 settled, for the stages that need it

Read off `BA-1`/`BA-3` while writing the above; none of it needs re-deriving.

- **Line numbers** 0–99999 (`comp`'s `bxh 6,2`), **at most 240 lines** (`f` is a
  480-word table, two words a line, `bxh 481,3`).
- **One statement to a line.** There is no separator; `comp` expects a CR after
  the statement.
- **Operators** are the negative entries in `s`, and their order is their
  precedence: `↑` binds tightest, then `*` and `/`, then `+` and `-`. `↑` is the
  ASR-33's up arrow, and there is no `**` and no `^`.
- **Relations** are `if`'s own decoder: `=`, `<`, `>`, `<=`, `>=`, `<>`. `=<` and
  `=>` are not accepted.
- **`PRINT`** separates with `,` (tab to the next zone, `ztab`) and `;` (no gap,
  `zsht`), and ends the line unless the last item carried one.
- **`INPUT`** takes a comma-separated variable list and no prompt string.
- **Arrays** default to 10 by 10 (`var27` reserves 11 by 11) and take one or two
  subscripts; `(` and `[` are the same bracket to the compiler.
- **`FOR`** nests about thirteen deep (`n` is 42 words, three a loop,
  `bxh 39,3`).
- **The run-time error strings** are `er0`–`e13` at the head of `BA-3`, and they
  are shorter than the list above: "out of data", "square root of negative
  number", "log of negative number", "log of zero", "program over time limit,
  test aborted.", "return before gosub", "subscript error", "division by zero",
  "overflow", "underflow", "zero to a negative power", "absolute value raised to
  power", "gosubs nested too deeply", "input data not in correct format, retype
  it." — with no `?` on any of them. The compile-time set is `lab1`–`lab23` at
  the end of `BA-2`, and it adds "cut program or dims." to the list above.
- **`TIME`** is a statement the source guards as "not legal in regular basic" (it
  belongs to the TEACH half), so it is not part of this dialect.

### What Stage 2 settled, for the stages that need it

Read off `BA-1`/`BA-2`/`BA-3` while writing the above; none of it needs
re-deriving, and the samples in particular should be written against it.

- **`PRINT` zones are fifteen columns and there are five of them**, so items
  land at 0, 15, 30, 45 and 60 (`ytab` divides the line by five three-character
  words and gives up after four). A comma inside the fifth zone starts a new
  line; one exactly at its start prints there.
- **A semicolon prints nothing.** The gap between two numbers is the pair of
  blanks every number carries. It only acts at column 66 (`ysht` against 22
  words), where it breaks the line.
- **A trailing `,` or `;` holds the line open**; without one, `PRINT` ends the
  line. A bare `PRINT` is a blank line.
- **Numbers print in two shapes.** A whole number below 2^30 prints as a sign
  (blank when positive), the digits, and two trailing blanks. Everything else
  prints to six significant digits, the seventh rounding the sixth, trailing
  zeros dropped, and moves to `.123456 E 07` when it outgrows the plain field —
  mantissa scaled below one, a blank rather than a `+` on a positive exponent.
- **Every run ends with the time it cost**: two carriage returns, then
  `time N secs.`. Time-sharing charged for the processor and said so.
- **A run-time fault prints `<message> in <line>` and stops.** All fourteen
  terminate — the run-time's message table marks them that way — so nothing in
  this dialect resumes, `INPUT`'s retype being the one exception.
- **Nesting limits:** `FOR` thirteen deep (the compiler's 42-word loop table,
  three words a loop), `GOSUB` 162 (the run-time's return stack is the gap
  between its working storage and the generated constants, one word a return).
- **The float format's exponent is the top nine bits of the first word**
  (masked with `0o3774000`), so the magnitude runs to a little under 10^77
  either way; past it is `overflow`, below it `underflow`.
- **`RND` gives the same sequence on every run.** There is no `RANDOMIZE` to
  break it, which is why the era's programs ask the user for a number and fold
  it in themselves — a sample that wants variety has to do the same.
- **Faults are found in two passes here**, which is the one deliberate
  divergence: the structural ones before the run as the compiler found them, a
  malformed formula when its line executes. Same message, same line, later
  moment.

### What Stage 3 settled, for the stages that need it

- **The keyboard's vocabulary is a pair of exported functions**, not a table to
  re-derive: `tokenToChar(token, shift)` and `ge235KeyTokens()` in
  `interpreter/keyboard.ts`. Stage 7's `symbolKeys` and `cursorKeys` batteries
  can be answered from them.
- **The SYM pages map twenty symbols**, and page 2 carries exactly one (`\`).
  Every printable code in the charset is reachable from the on-screen keyboard,
  which the layout test asserts code by code.
- **`powerOnCase` stays absent and there is no case pair or case lock** — the
  shape `layoutGeometry.test.ts` requires of a machine with no lower case. The
  `LETTER_CASE` entry Stage 7 adds folds on all four counts, the keyword scan
  because no lower-case letter can reach it rather than because anything folds
  it.
- **Three sample deviations are the hardware's**, and are written down in
  `samples.ts`: the maze is steered by `1 2 3 4` because `INPUT` reads numbers
  and nothing else reads the keyboard; its walls are `*` because the set has no
  `#`; and `YOU ESCAPED.` ends in a full stop because the set has no `!`.
- **A table in `DATA` may hold 128 constants**, which is what sizes the maze's
  map at 13 by 9.
- **A `FOR` whose limit is already passed still runs its body once**, so a
  sample cannot use `FOR S=1 TO 0` as "no iterations" — `hello` counts from 1.

### What Stage 4 settled, for the stages that need it

- **The tape is not ASCII, and that was the plan's one wrong guess.** The
  machine's codes are 6-bit BCD, so two things the Altair's paper tape does
  cannot be done here: a `{0oNN}` escape is written spelled out rather than
  resolved to the byte it names (that byte would be a BCD code no reader of a
  text file could show), and the end-of-message code does not close the file.
  Both keep the file openable and the round trip exact.
- **`↑` is written as itself**, not as `^`. `charset.test.ts` asserts outright
  that `^` has no GE-235 code, so writing one would produce a file the editor
  could not read back — and the ASCII revision that spells the up arrow `^` is
  two years later than the machine anyway.
- **`buildPaperTape(source)` is exported** for anything downstream that wants
  the listing bytes; it throws on an empty program and on fatal tokenizer
  errors, and a missing `END` is only lint, so a program the compiler would
  complain about still punches a full tape.

## Stage 5 — Memory map ✅

Introspection is deferred, so this stage is the map alone.

      reasoning is below
- [x] **no `memoryBlocks`**, and the check that wants one is not in

- [x] **no** `readMemoryStats`, **no** memory-activity hooks — deferred
- [x] tests: `memoryMap.test.ts` — the tiling, every boundary against the octal

### What Stage 5 settled, for the stages that need it

- **8,192 words is half the store, and the right half.** `top: eqo 17777` is
  what the listing calls the top of lower memory, and it is what one
  instruction's thirteen-bit address field reaches. The second bank is the
  executive's "system read-in area": the compiler itself is assembled to run
  from octal 20000 up, and a compiled program cannot reach it without the bank
  bit — which is exactly why 1280 words of constants and run-time subroutines
  are copied down into lower memory before a program runs. Mapping the second
  bank would be mapping whichever language the executive last read in, so the
  map is the bank the user's program lives in and the file says why.
- **The 6K area is the unit the machine swaps.** Octal 4100 to the top, 6,080
  words, goes to disk when the next user's turn comes; below it the executive is
  resident. That is the split the map's bands draw.
- **Two cross-dialect assertions fail the moment this dialect is registered.**
  Confirmed by registering it and running the battery, not by reading it, and
  both are in `memoryMap.test.ts` rather than `memoryMapDetail.test.ts` (which
  is a hand-listed matrix of five machines and is indifferent to a sixth):
  - _"spans the same address space on every machine, which the side-by-side
    comparison assumes"_ — every other map is `0x10000` and this one is
    `0x2000`. The test's own comment says a machine with a different address
    space should fail here by name so the comparison gets a decision, and this
    is that machine. The porting guide draws both panes at the same pixels per
    unit, so a shorter column is drawn correctly; what it stops being able to
    claim is that a line across the two panes is one address on both machines,
    since one side's unit is a byte and the other's is a twenty-bit word.
  - _"starts the program region where the dialect says the program begins"_ —
    it reads the base out of `memoryBlocks` and asserts it is **defined** rather
    than skipping, deliberately, so a dialect that ships a map cannot pass by
    doing nothing. A machine offered as BASIC only has no blocks and no base to
    agree with, so the exemption has to be explicit and has to keep asserting
    something: that this dialect genuinely cannot place code at an address.
    Registering the map alone also fails `machineArt`, `memoryActivity` and
    `programRamBudget` — all three already on Stage 7's list, all three wanting a
    reason rather than data.
- **`addressNotation` was not widened, and `'dec'` is the honest answer here.**
  The field only chooses which way the viewer's Int/Hex toggle opens. Nothing in
  this BASIC takes an address — no `PEEK`, no `POKE`, no `USR` — so no program is
  ever written in the notation, and the octal the machine's own listings use is
  carried in the map's notes, where it reads as history rather than as a third
  global toggle state. Adding `'oct'` is not the one-line change it looks: the
  union in `types.ts`, `MemoryMapView`'s `Notation` and its address formatter,
  the IDE panel's toggle, the porting guide's Vue wrapper, `reference/facts.ts`
  and `registry.test.ts`'s notation table would all take a third state, for one
  machine.
- **The map pins three of the interpreter's limits.** 240 lines, 128 `DATA`
  constants and 162 nested `GOSUB`s are all the same allocation arithmetic
  divided by what one entry costs, so `MAX_LINES`, `MAX_DATA_CONSTANTS` and
  `MAX_GOSUB_DEPTH` are asserted against the map (the latter two gained an
  `export` for it). The `DATA` region landing on a multiple of 64 is the
  compiler's own stated reason for the 22 words of padding above it, and
  checking it checks the whole chain of reservations underneath.
- **`programRamBytes` is still 0.** The field is bytes and the byte counter
  compares it against a source length in characters; the figure the map gives is
  4,139 _words_ of object code and variables. Reconciling the two is
  `programRamBudget`'s exception at Stage 7, not this stage's.
