## Machine code & data blocks

A ZX80 program can carry machine code or data — **memory blocks** — by hiding the
bytes inside a `REM` line, so they travel in the single standard `.O` file that
real emulators and hardware load. The bytes live in the program listing itself.

Each hidden-code `REM` line shows in the editor as a **block tab** next to the
BASIC tab. Open the tab to edit the block's assembly; saving rewrites the hidden
`REM` line, keeping the machine code part of the program. Add a block with the
**+** button, or import a `.O` that already holds one and the IDE gives it a tab.

A block's **address is fixed by where its `REM` line sits** — the address is shown
in the block tab and can't be typed in; move the `REM` line to change it. You can
mark a block as **code** or **data** and name it; those labels are remembered in
the [project bundle](./file-formats#project-bundle-bproj).

One ZX80 caveat: a line ends at a newline byte, so a block can't hold that byte
(`0x76`, the Z80 `HALT` opcode) — the editor tells you if your code hits this.
Because the bytes ride in the listing, they export and import with the ordinary
`.O` file and run on a real ZX80 unchanged.

See the [machine code guide](../guide/machine-code) and the cross-dialect
[Machine code & data blocks](./file-formats#machine-code-data-blocks) overview.
Every mnemonic, directive and operand form the assembly editor accepts is in the
