## Machine code & data blocks

A ZX81 program can carry fixed-address machine code or data — **memory blocks** —
that load into RAM alongside the BASIC program. On the ZX81 a block may sit from
**0x4000 to 0x7FFF**; new blocks default to **0x7000**, high in RAM clear of a
typical program. The system variables at **0x4000–0x407C** are reserved with a
warning — a block there loads, but the running ROM may overwrite it.

The block bytes are written the instant the program loads, before it auto-runs,
so the program's own `PEEK` or `USR` sees them already in place.

The `.P` file holds only the BASIC program (and can't carry data above the used
RAM), so a block is imported from a **sidecar file** instead: drag a
`<name>-<addr>.bin` (for example `sprite-0x7000.bin`) onto the editor to add its
bytes as a block at the address in its name. Blocks also travel with a ZX81
document through the [project bundle](./file-formats#project-bundle-bproj) or a
share link. On Run the IDE refuses to start if a block would overlap the BASIC
program, and warns (but allows) a block over the system variables.

See the [machine code guide](../guide/machine-code) and the cross-dialect
[Machine code & data blocks](./file-formats#machine-code-data-blocks) overview.
